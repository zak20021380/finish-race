# 2026-10-14 (3) — Admin Command Center, Part 2: the live server

## What changed
The panel now governs the Cloudflare Worker too, not just local state.

- **`worker/env.ts`** — `ADMIN_IDS?: string` (comma-separated Telegram ids). Also documented as an
  empty `ADMIN_IDS = ""` var in `wrangler.toml`.
- **`worker/auth.ts`** — `verifyAdminRequest(request, env)` → `AdminIdentity | null`. Reads the
  initData from `X-Telegram-Init-Data`, `Authorization: tma <initData>`, or `?initData=`; verifies
  the HMAC (reusing the private `verify()`), then checks the id is on `ADMIN_IDS`. A *valid*
  signature always wins; failing that the dev door needs BOTH a dev host (`DEV_AUTH="true"` or
  loopback) AND an explicit marker (`x-admin` / `x-detour-admin` header, or `?admin=1`). Takes an
  `AdminRequestLike` (`{url, headers.get}`), not a real `Request`, so it is testable in plain Node.
- **`worker/index.ts`** — `/admin/*` is verified first and answers **403** when refused, then the
  original request is forwarded to the same `MatchmakerDO`. `/health` and `/ws/matchmake` untouched.
- **`worker/matchmaker.ts`** — the DO gained `maintenance`, `normalRadius`, `wideRadius` (defaults
  250/600) and routes `/admin/status`, `/admin/config`, `/admin/action` in `fetch()` *before* the
  upgrade check. `take()` now reads the live radii. `enqueue()` refuses a QUEUE under maintenance
  with `{type:"ERROR",reason:"MAINTENANCE"}` + clean close; turning the lock on calls `evictAll()`
  which notifies and closes everyone waiting. `CLEAR_QUEUE` → `evictAll('CLEARED')`; `ABORT_MATCH`
  → `settle()` then `{type:"ABORTED",matchId}` + close on both seats.
- **`index.html`** — a 4th tab (`data-atab="server"`) + `#apanel-server` card: `#adm-server-chip`,
  `#srv-queue`, `#srv-rooms`, `#srv-list`, `#srv-refresh`, `#srv-clear`.

- **`src/admin.ts`** — server types (`ServerConfig`, `ServerStatus`, `QueuedPlayer`, `ActiveRoom`),

## Why the 4th tab (not the Live Ops panel)
`.tmp/admin-check.mjs` walks EVERY element of `#overlay-admin` and fails on `bottom > innerHeight`,
including elements scrolled out of an `overflow-y: auto` body. The Ops panel already fills 360x640
exactly, so any new card there breaks the check. A hidden panel has zero-height children and is
skipped — a new tab is the only safe place for more content.

## Follow-up — the client now understands the server's refusals
Server-side enforcement was correct but the client did not parse the frames it produced, so a
refused queue fell through to `simulatedSearch()` and the player got a **bot race anyway** — which
defeats the whole point of a maintenance lock.

- **`src/matchmaking.ts`** — `RaceFrame` gained `{type:'ERROR',reason}` and `{type:'ABORTED',matchId}`;
  `parseFrame` reads both. A refusal is deliberately *not* an abort: it travels as an `Error` whose
  `name` is `'queue-refused'` and which carries `reason`, so `queue()`'s rejection handler can tell
  "the server said no" from "the socket died" and skip the local fallback (`refusedStage()` →
  `teardown` + `hide` + `init.onRefused(reason)`). `refuseSearch()` clears `ws`/`seat` *before*
  closing, so the close event is a no-op rather than a second settle. `RaceEnd['why']` gained
  `'aborted'`; an `ERROR` on a racing socket and an `ABORTED` both end the race.
- **`src/main.ts`** — `onRefused` shows the same maintenance wording the local lock uses (and a
  different line for `CLEARED`), then reopens the mode drawer; `endOnline` maps `aborted` to
  "Room closed by an operator" instead of "Connection lost".
