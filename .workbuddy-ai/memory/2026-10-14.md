## Follow-up — the client now understands the server's refusals
Server-side enforcement was correct but the client did not parse the frames it produced, so a
refused queue fell through to `simulatedSearch()` and the player got a **bot race anyway** — which
defeats the whole point of a maintenance lock.

- **`src/matchmaking.ts`** — `RaceFrame` gained `{type:'ERROR',reason}` and `{type:'ABORTED',matchId}`;
  `parseFrame` reads both. A refusal is deliberately *not* an abort: it travels as an `Error` whose
  `name` is `'queue-refused'` and which carries `reason`, so `queue()`'s rejection handler can tell
  "the server said no" from "the socket died" and skip the local fallback (`refusedStage()` →
  `teardown` + `hide` + `init.onRefused(reason)`). `refuseSearch()` clears `ws`/`seat` *before*
  closing, so the close event is a no-op rather than a second settle. `RaceEnd['why']` gained
  `'aborted'`; an `ERROR` on a racing socket and an `ABORTED` both end the race.
- **`src/main.ts`** — `onRefused` shows the same maintenance wording the local lock uses (and a
  different line for `CLEARED`), then reopens the mode drawer; `endOnline` maps `aborted` to
  "Room closed by an operator" instead of "Connection lost".

## Wall geometry: no `+` crossings, and one board mode at a time

Two bugs, one commit's worth of work. (a) The rules let a vertical wall cross a horizontal one
through the vertex they both hinge on, drawing a `+` on the grid. (b) A dashed wall preview and a
picked ball's move dots were painted on top of each other, because a hover/arm never cleared the
ball in hand and the dots were not derived from the preview at all.

### src/rules.ts — the geometry, named
- A wall is **two edge segments plus the vertex they hinge on**. That lattice now has a name:
  `Vertex {x, y}`, `wallVertices(w)` (ends + hinge), `wallPivot(w)` (`h(x,y)` → `(x+1, y)`,
  `v(x,y)` → `(x, y+1)`).
- `wallSegments(w, out)` keys the two segments into one number space (`SEG_V = COLS*ROWS` offsets
  the vertical family, so the two can never collide) and writes into a module-level scratch pair —
  `botAction` calls this inside an 88-iteration loop.
- Three predicates, all allocation-free: `wallsOverlap` (same orientation, any shared segment key),
  `wallsCross` (**different orientation and identical pivot** — the illegal `+`), `wallsClash` (both).
- `wallOk` is now `for (const o of s.walls) if (wallsClash(o, w)) return false;`.
- **The exact rule, which is easy to get wrong:** only a *shared pivot* is illegal. A wall whose
  endpoint lands on another wall's midpoint is a T-junction and stays legal; two ends meeting is an
  L-corner; collinear walls touching end to end (x and x+2) stay legal. Do **not** widen this to
  "any shared vertex" — that would outlaw every T-junction the task explicitly keeps.

### src/boardmode.ts — new, pure, testable
The board has one action mode: a ball in hand, a wall preview, or the mine key. That rule used to
be a scatter of assignments in `main.ts`, so it could not be asserted without a browser. It is now
a generic `BoardMode<P>` plus `BOARD_IDLE`, `pickBall` (clears the preview), `previewWall` (clears
the ball in hand — but `previewWall(m, null)`, the pointer leaving the board, only drops the bar),
`holdMineKey`, `moveDots`, `selectionRing`. No imports at all, so a test can read `src/boardmode.ts`
directly.

### src/main.ts — the wiring, and the part that actually bit
- `mode()` / `setMode(next)` are the only writers of `selected` / `ghost` / `mineArmed`;
  `setMode` also calls `armCapsules()`, so the `[✓]/[✕]` caps follow the preview automatically.
  `clearGhost`, `pick`, `armMine`, `tapWall`, the `onMouse` hover branch, `pointerleave`, `play`,
  `timeoutMove` and `restart` all route through it (`play`/`restart`/`timeoutMove` use `BOARD_IDLE`).
- **`hints` is derived, and that was the real bug.** `setMode` recomputes it via `dotsFor(mode())`
  (`canAct() && moveDots(m) && selected !== null`). Before, the dots were computed from
  `selected !== null && !mineArmed` only, and `onMouse`'s hover branch set the ghost *without*
  calling `ui()` — so `hints` stayed stale and the dots kept painting under a fresh dashed bar.
  Lesson: when a value becomes derived from a mode, every writer of that mode has to recompute it.
- The frame loop reads one `mode()` per frame and sets `v.sel = dots && v.id === m.selected`, so the
  selection ring goes with the dots. `wallIssue` gained a `'cross'` reason (`REASON.cross`).
- The auto-pick at the start of a human turn is gated on `!ghost` as well.

### src/render.ts — drawBar cap inset
`x0 = cap + Math.min(2, c * 0.06)` and `len = 2c - 2*x0`, then gloss / rim / cross-bands all hang
off `x0` instead of `cap`. Round caps hang `t/2` past the stroke, so the body still spans very
nearly the two cells, but an L-corner or a T-junction now stops ~2px short of the perpendicular
wall instead of bulging over it.

# 2026-10-14 (4) — Multi-player board scaling, Part 1: dynamic grid dimensions

## What changed
The board is no longer a fixed 8x12. The rules size the grid to the race, and the start squares are
spaced instead of clustered.

- **`src/rules.ts`** — `GameState` gained `cols` / `rows` (the only source of truth). New
  `Dims` / `dimsFor(contenders)` (8x12 for ≤2, 10x12 for ≥3), `contendersIn(sizes)` (**contenders =
  total balls, not seats**), `wallBudget(contenders)` (8/6/5 for 2/3/≥4), `spawnColumns(cols,count)`,
  `spreadOf`, `hasPathToFinish(s, walls?)`. `MAX_TEAMS` 3 → 4. `COLS`/`ROWS` stay as the duel
  defaults *and* the arg defaults on board-shape helpers (`allWalls`, `startLayout`, `logStopRow`,
  `hazardAt`, `hazardSchedule`, `initPhase`), but `distField(walls, cols, rows)` and
  `pathOn(d, pos, cols)` now take dims as **required** args.
- **Lattice keys are dimension-free.** `blocks()` and `wallSegments()` key on `LATTICE_C`/`LATTICE_R`
  (the largest board), so `wallsOverlap` / `wallsCross` / `wallsClash` take no dims at all and the
  existing pure-geometry tests kept working untouched.
- **`startLayout`** fills rows bottom-up; rows above the first draw from the columns the rows below
  left free, so no ball starts stacked on another while the board has room. Guarantees: 1v1 → 2, 5;
  3-way → 1, 5, 8; 4-way → 1, 3, 6, 8. A crowded board (12 balls / 10 columns) cannot keep everyone
  apart and falls back to the plain spread.
- **`src/hazards.ts`** — `hazardAt(seed,k,cols)` / `hazardSchedule(seed,n,cols)` / `initPhase(seed,cols)`
  / `logStopRow(walls,left,width,rows)`; `runLog` and `tickHazard` read `s.cols`/`s.rows`, so the
  trunk sweeps the full width and reaches the true bottom of whichever board it is on.
- **`src/bot.ts`** — every key/path/`allWalls` call threads `s.cols`/`s.rows`; it plays the wide board
  correctly with no special casing.
- **`src/render.ts`** — `cols`/`rows` became `let` and the renderer gained `setBoard(c, r)` (resets
  `lastW` to force a relayout). `sceneView`'s `GameState` literal needed the two new fields, and
  `TEAM3_RAMP` was added to `themes.ts` + `FIXED` because a 4th seat is now playable and would
  otherwise have worn the "illegal" red.
- **`src/main.ts`** — `restart()` calls `renderer.setBoard(state.cols, state.rows)` and sets
  `wallsEach = wallBudget(state.balls.length)` (the chip's aria-label no longer hardcodes 8);
  `wallIssue` and `playLog` read the board's own dims.
- **`worker/matchmaker.ts`** — `readMessage(raw, side, cols, rows)` via a new `boardOf(waiter)`, so the
  room accepts the wide board's extra columns instead of dropping them as off-board. Same fix on the
  client in **`src/matchmaking.ts`** (`parseFrame(raw, sizes)` → `onBoard(v, cols, rows)`).

  (r > b+60 / b > r+60 / neither) and take the brightest column of each run.
- **The menu has two start paths.** `gm-start` in the game-mode drawer overrides sizes with
  `sizesForMode(id)`, so a `localStorage` sizes override does nothing there — use the
  `[data-preset="2,2"]` preset button or the vs-Bot card (`[data-start="bot"]`), which read
  `menuState.sizes`.
- `rollup` warns "Circular dependency: src/rules.ts -> src/hazards.ts -> src/rules.ts" on every bundle;
  pre-existing and harmless (rules re-exports from hazards, which imports rules).

## Four real bugs the harness caught (all fixed in `src/`)
1. **`drawBall` threw `IndexSizeError: arc radius (-0.1328) is negative`**, aborting every frame —
   the board read as *blank* and looked like a harness failure. The "crisp edge" ring was
   `ctx.arc(0, 0, r - 0.5, …)` and on a degenerate cell (`cell ≈ 1.08`) `r < 0.5`. Clamped to
   `Math.max(0, r - 0.5)`. Only unclamped radius subtraction in the file — `grep -n "\.arc("` is the
   audit.
2. **The renderer could keep a stale layout forever.** `resize()` runs from `setBoard` and a
   `ResizeObserver` on `.board-wrap`; a race built while its screen was hidden measured `0x0`, and a
   wrap that was *already* sized fires no observer on reveal. `draw()` now self-heals: if
   `canvas.clientWidth/Height` differ from `lastW/lastH`, re-fit before painting (two property reads
   per frame, `buildStatic` only on an actual change).
3. **Board furniture spilled outside the slab.** With the grid now letterboxed inside a box of its
   own aspect, the canvas no longer clips for it: a bottom-row ball's selection ring (`r * 1.6`) and
   turn halo (`r * 2.3`) painted a crimson arc on the card below the board. One
   `rr(...)+clip()` to the slab, opened right after `setTransform` and closed at the end of `draw`
   (balanced — `draw` has no early returns), covers the sweep, tints, walls, mines, pulses, blasts,
   balls, log and thinking pips.
4. **`#gm-start` kept saying "Start practice match".** `gamemodes.ts` `setGameMode` fires its
   watchers and *then* calls `paintSheetState()`, so no `onGameModeChange` hook can ever be the last
   writer; the diff-button handler also calls it directly. Registering `paintParty` after
   `initGameModes` was necessary but not sufficient. Fix: a `MutationObserver` on `#gm-start` that
   re-speaks the seat count whenever the drawer repaints it, with an equality guard in `paintParty`
   so our own write cannot re-enter (settles in one pass).

## New wiring
- **`--board-oy`** is published from `publishCell()` alongside `--board-cell`. The slab is centred in
  the canvas, so row 0 starts at `oy`, not 0 — a 10x12 board in a 328x394 box sits at `oy = 5`. The
  finish plate's `top` is now `calc(var(--board-oy, 0px) + var(--board-cell, 36px) / 2)`. It was
  `100% / (2 * var(--board-rows))`, which assumes `oy = 0` and put the plate ~5px off the strip.
- Party entry: `[data-seats]` 2/3/4 on the Practice card, persisted at `detour.party.v1`;
  `localSizes()` gives one ball per seat above 2.

## Harness lessons (`.tmp/board-scale-check.mjs`)
- **Calibrate `ox`/`oy`/`cell` from the alpha>=250 bounding box**, not from a colour feature. The
  first version derived `ox` from the finish strip's leftmost near-white pixel — but the checkers
  alternate and the strip *starts green* on these boards, so that pixel is the **second** checker.
  `ox` came out half a cell wrong and reported a 336.8px right edge on a 328px canvas, plus every
  ball straddling two columns. A drop shadow (a blur of a translucent colour) never reaches alpha
  250; every glow/ring/streak is blended. The bbox is exact.
- **Find a ball by centroid, not by per-column pixel counts.** The seat to move wears a halo at
  radius 0.78 cell vs the ball's 0.34, so one crimson ball voted as three adjacent crimson columns.
  A radial halo is centred on its ball, so a saturation×alpha-weighted centroid lands on the ball
  with the halo in or out; then require it within 0.12 cell of a cell centre.
- **The magnet probe has to run on the opening position.** "A ball outranks the groove" tapped
  spawn column 1 at row 11 *after* the bots had moved, so the square could be empty and the test
  flaky. Asserted first, while the board is still in `startLayout`, it is exact.
- **Viewport px vs canvas-local px**: the plate assertion compared `getBoundingClientRect()` to a
  `getImageData` offset and failed by the canvas's own top. Subtract `canvas.top`.
